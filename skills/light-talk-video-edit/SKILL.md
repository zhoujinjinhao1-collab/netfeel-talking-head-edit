# 浅色口播剪辑

交付实际可播放的视频。默认视觉方向：米白底、鼠尾草绿、少量杏色、浅底深字字幕、柔和阴影、圆角人物窗与分步图解。用户指定的品牌、风格、节奏和编辑软件优先。

## 先确定这次改什么

- 新口播：检查原片和语音，整理字幕与剪切点，再设计适合内容的画面。
- 已有版本的视觉精修：复用已确认的剪切时间轴与音频，主要调整包装；另存版本以便比较。
- 用户说“先试一下”：先交付能看的试剪，并说明少量实际缺失的素材。不要停在方案或效果图。

先读 [设计规范](references/design.md)。使用附带的 Python 渲染器时，再读 [配置与执行](references/rendering.md)；需要本地语音识别或补齐工具时读 [运行环境](references/runtime.md)。

## 剪辑与内容判断

1. 读取时长、尺寸、帧率和音轨；按段抽帧，关键切换处加密检查。语音识别不能替代听辨，口音词、金额、人名和否定词优先核对，无法确认的词记录待核。
2. 将字幕原始时间和成片时间分开。先确定保留的原片区间，再映射字幕和视觉提示；切掉重复句时检查有没有截断音节、改变论点或错接主语。
3. 让每次视觉变化承担任务：截图展示资料、照片展示对象、节点表达连接、卡片作并列、列表承载顺序。保留适量人物画面，让图解段与人物段交替。
4. 柔边、圆形或圆角小窗可以保留原背景；只有需要独立人物前景时才做人像分割。每条原片重新确认小窗裁切，不能沿用上次的人脸坐标。
5. 对外部图片先做裁切、明暗和版式统一，并保存来源。只有照片时用轻微推拉；物体翻动、变形和微缩场景内部运动需要单独动画素材。不要把旧视频的照片、口播论点或案例自动带进新片。
6. 图解和标题不新增原片没有的统计数字、新闻引文、官方凭证或保证性结论。用户的口播观点与独立核验材料要分清。

## 制作入口

可用既有编辑器完成，也可以使用附带的可配置渲染器。它支持 9:16、720×1280 的快速试剪，含人物标题卡、照片版、连接图、并列卡片和稳定性示意图；模板名称只决定构图，文字、图标、时序和素材由当前任务配置。

```text
scripts/render_light.py --config 项目配置.json --check
scripts/render_light.py --config 项目配置.json --preview
scripts/render_light.py --config 项目配置.json
```

配置与路径均从参数传入，不依赖本次工作区。超出此画布、模板或交付格式时，根据设计规范适配工具，不强行把内容塞进模板。首次测试可从 [assets/example-project.json](assets/example-project.json) 改起；这是示例数据，不是预设的口播事实或时间点。

## 导出与检查

- 先抽查开头、各版式、最长字幕、全部小窗和结尾，再导出；修正缺字、遮挡、低对比度和拥挤。
- 完整解码成片，核对实际时长、音轨、剪切点与字幕同步。附带的 `scripts/verify_video.py` 可检查解码、时长及音频是否与指定版本一致；它不证明字幕正确，也不代替看/听。
- 只改包装时，若承诺保留音频，优先复用原音轨并核对内容；不要无意重新混音。
- 给出 MP4、简短变更说明，必要时附画面预览和待补素材。保留配置、字幕与脚本，方便下一轮修改。不要把配置 JSON 称为剪映、PR 或其他软件的原生工程。

## 在真实使用中更新

把新的偏好写入对应设计规范或配置字段。某条片的主题、人物、剪切位置和素材放在该片项目内，避免污染通用技能。
